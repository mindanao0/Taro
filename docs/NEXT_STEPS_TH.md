# ต้องทำอะไรต่อ (สรุปสำหรับผู้ดูแลเว็บ)

โค้ดทั้งหมดเสร็จและผ่านเทสต์แล้ว (ทดสอบกับ provider จำลองและ runtime จำลองของ Cloudflare) **ที่เหลือคืองานที่ต้องใช้บัญชี เครื่อง หรือคนจริง** ไฟล์นี้เรียงตามลำดับที่ควรทำ ติ๊ก `[x]` เมื่อทำแล้ว

ตอนนี้เว็บยังใช้งานได้ตามเดิมโดยไม่ต้องทำอะไรเลย (เลือกไพ่, อ่านความหมาย, แค็ตตาล็อก) ระบบสมาชิก ประวัติ ไพ่โปรด ไพ่ประจำวัน และแจ้งเตือน LINE **ปิดอยู่** จนกว่าจะตั้ง `API_URL` ในขั้น 6

ตัวช่วย: `node scripts/launch-check.mjs` แสดงรายการที่ยังค้างจริง ๆ ณ ตอนนั้น (`--strict` ให้ล้มเหลวถ้ายังค้าง)

## ส่วน A: ต้องตัดสินใจและเตรียมของก่อน

- [ ] **A1. ตัดสินใจว่าจะเปิดระบบสมาชิกหรือไม่** ถ้าไม่เปิด ข้ามไปส่วน D ได้เลย (เว็บที่มีอยู่ใช้งานได้ครบ)
- [ ] **A2. เตรียมบัญชีกลางของโปรเจกต์** (ไม่ใช้บัญชีส่วนตัวของคนใดคนหนึ่ง และใส่ผู้ดูแลอย่างน้อย 2 คน): Cloudflare, Resend, Google Cloud, LINE Developers, Meta for Developers (เฉพาะเจ้าที่จะเปิดใช้ ไม่ต้องเปิดครบทุกเจ้า)
- [ ] **A3. เปิด 2FA** ที่บัญชี Cloudflare และบัญชีที่ใช้ดูแลทั้งหมด เพราะผู้ที่เข้า Cloudflare ได้ เข้าถึงข้อมูลผู้ใช้ได้
- [ ] **A4. ใช้แพ็กเกจ Workers แบบเสียเงิน** สำหรับ `taro-api` การแฮชรหัสผ่านใช้เวลา CPU มากกว่าที่แพ็กเกจฟรีรองรับ (ตามที่ทราบ แพ็กเกจฟรีจำกัดประมาณ 10 มิลลิวินาทีต่อคำขอ ตรวจเงื่อนไขล่าสุดที่เอกสาร Cloudflare ก่อน)
- [ ] **A5. นโยบายความเป็นส่วนตัวและข้อกำหนด** (ต้องเสร็จก่อนเปิดให้ผู้ใช้ทั่วไป และ Facebook บังคับให้มีลิงก์นี้)
  - เปิด `privacy.html` และ `terms.html` กรองช่อง <span>`[ในวงเล็บ]`</span> ทุกช่อง (ชื่อผู้ควบคุมข้อมูล, ที่อยู่, อีเมลติดต่อ, ระยะเวลาสำรองข้อมูล ฯลฯ)
  - **ให้ผู้เชี่ยวชาญกฎหมายตรวจ** (โดยเฉพาะการโอนข้อมูลไปต่างประเทศ เกณฑ์อายุ และข้อจำกัดความรับผิด) เอกสารเป็นฉบับร่างที่เขียนจากสิ่งที่ระบบเก็บจริง ไม่ใช่คำแนะนำทางกฎหมาย
  - ลบกล่อง "ฉบับร่าง" (องค์ประกอบ `id="draft"`) ออกจากทั้งสองไฟล์ หลังตรวจเสร็จ
  - ถ้าแก้สาระสำคัญภายหลัง ให้เปลี่ยน `POLICY_VERSION` ใน `scripts/config.mjs` ผู้ใช้จะถูกขอให้รับทราบอีกครั้ง

## ส่วน B: ตั้งค่าบริการภายนอก

- [ ] **B1. Resend (อีเมล)** ทำตาม `docs/DEPLOY_API_TH.md` ข้อ 1: เพิ่มโดเมน, ใส่ DNS (SPF/DKIM) ที่ Cloudflare, รอ Verified, สร้าง API key
- [ ] **B2. Google** (ถ้าจะเปิด) ข้อ 6: สร้าง OAuth client, redirect URI `https://api.ivoryrosetarot.online/auth/google/callback`
- [ ] **B3. LINE Login** (ถ้าจะเปิด) ข้อ 7: สร้าง channel ใน Provider ของโปรเจกต์, ขอสิทธิ์อีเมล, callback URL
- [ ] **B4. Facebook** (ถ้าจะเปิด) ข้อ 8: ต้องมี Privacy Policy URL (จากข้อ A5) และช่องทางลบข้อมูลก่อนสลับแอปเป็น Live
- [ ] **B5. LINE Official Account** (ถ้าจะเปิดแจ้งเตือน) ข้อ 9: ต้องอยู่ใน **Provider เดียวกับ LINE Login** ตั้ง webhook เป็น `https://api.ivoryrosetarot.online/line/webhook` และตรวจโควตาข้อความของแพ็กเกจ

## ส่วน C: Deploy ระบบสมาชิก (ทำจากโฟลเดอร์ `api/`)

ติดตั้งเครื่องมือครั้งเดียว: `npm install` (ที่โฟลเดอร์หลัก) และ `wrangler login`

- [ ] **C1.** สร้างฐานข้อมูล `wrangler d1 create taro` แล้วใส่ `database_id` ที่ได้ใน `api/wrangler.toml`
- [ ] **C2.** `wrangler d1 migrations apply taro --remote`
- [ ] **C3.** ใส่ secret ด้วย `wrangler secret put <ชื่อ>`: `RESEND_API_KEY`, `COOKIE_SECRET`, `DAILY_SECRET` (สองตัวหลังสร้างด้วย `openssl rand -base64 48`) และของ provider ที่เปิด (`GOOGLE_*`, `LINE_CHANNEL_*`, `FACEBOOK_APP_*`, `LINE_MESSAGING_TOKEN`, `LINE_MESSAGING_SECRET`) ปุ่มของ provider ที่ไม่ได้ตั้ง secret จะไม่แสดงเอง
- [ ] **C4.** แก้ค่าใน `api/wrangler.toml`: `EMAIL_FROM` (โดเมนที่ยืนยันกับ Resend แล้ว), `LINE_OA_URL` (ลิงก์เพิ่มเพื่อน), ถ้าต้องการใส่ `SUPPORT_EMAIL`
- [ ] **C5.** `wrangler deploy` แล้วเปิดบรรทัด `routes = [...]` (เอา `#` ออก) และ deploy อีกครั้งเพื่อผูกโดเมน `api.ivoryrosetarot.online` **ต้องเป็นซับโดเมนของเว็บเดียวกัน** ไม่เช่นนั้น cookie ใช้ไม่ได้
- [ ] **C6.** ตรวจเบื้องต้น: `curl -s https://api.ivoryrosetarot.online/auth/providers` ควรได้รายชื่อ provider ที่เปิด

## ส่วน D: เปิดใช้ในเว็บและทดสอบของจริง

- [ ] **D1.** แก้ `export const API_URL = '';` ใน `scripts/config.mjs` เป็น `'https://api.ivoryrosetarot.online'` แล้ว commit และ push (เว็บจะมีลิงก์ "เข้าสู่ระบบ", ไพ่ประจำวัน และหน้า `account.html`)
- [ ] **D2. ทดสอบด้วยมือบนเว็บจริง** (ผมทดสอบกับของจริงไม่ได้):
  - สมัครด้วยอีเมล → ได้อีเมลยืนยันไหม (ดูโฟลเดอร์สแปมด้วย) → กดลิงก์ → เข้าสู่ระบบ
  - ลืมรหัสผ่าน → ลิงก์ใช้ได้ → ตั้งรหัสใหม่
  - เข้าด้วย Google / LINE / Facebook ทีละเจ้า (ถ้าเปิด) ทั้งบนมือถือและคอมพิวเตอร์
  - เลือกไพ่ → บันทึกลงประวัติ → ดูในหน้าบัญชี → เขียนโน้ต → ลบ
  - ไพ่โปรด, ส่งออกข้อมูล, ลบบัญชีแล้วเข้าสู่ระบบอีกครั้งเพื่อกู้คืน
  - แจ้งเตือน LINE: ผูก LINE → ยินยอม → เพิ่มเพื่อน → ตั้งเวลา → รอข้อความ → พิมพ์ "หยุด" ในแชต
- [ ] **D3.** รัน `node scripts/launch-check.mjs` ต้องไม่เหลือรายการที่เกี่ยวกับสิ่งที่คุณเปิดใช้

## ส่วน E: ตัวเก็บคำถามและลำดับการกด (ไม่บังคับ แยกจากระบบสมาชิก)

ทำเฉพาะถ้าอยากเก็บข้อความคำถามหรือสถิติการกด ตาม `docs/DEPLOY_TH.md`: สร้าง D1 `taro-log`, รัน migration, `wrangler deploy` (จากโฟลเดอร์หลัก) แล้วตั้ง `LOG_URL` และ/หรือ `TRACK_URL` ใน `index.html` ลำดับการกดเก็บเฉพาะเมื่อผู้ใช้ติ๊กยินยอม ต้องอธิบายไว้ในนโยบาย (มีอยู่แล้ว)

## ส่วน F: ก่อนและหลังเปิดจริง

- [ ] **F1.** ดูผล GitHub Actions รอบแรก (`.github/workflows/test.yml`) ผมเขียนไว้แต่ทดสอบรันบน GitHub ไม่ได้ ถ้าล้ม ส่งข้อความผิดพลาดมาได้
- [ ] **F2.** ลองแตะวงล้อไพ่บนมือถือจริงหลายเครื่อง (เทสต์ของผมใช้การสั่งคลิกจำลอง)
- [ ] **F3.** ให้ผู้เชี่ยวชาญทาโรต์ตรวจเนื้อหาความหมาย 78 ใบ และตัดสินใจเรื่องชื่อสำรับ (ตอนนี้เป็นชื่อทำงาน) และสิทธิ์ของภาพที่สร้างด้วย AI ตามที่ระบุใน `docs/06_QA_AND_PRINT_TH.md`
- [ ] **F4.** ตั้งการแจ้งเตือนใน Cloudflare/Resend ถ้ามี (อีเมลเด้งกลับ, ข้อผิดพลาดของ Worker) และอ่าน `docs/RUNBOOK_TH.md` เพื่อรู้วิธีเช็กระบบ สำรองข้อมูล หมุนความลับ และรับมือเหตุข้อมูลรั่ว (แจ้งภายใน 72 ชั่วโมง)
- [ ] **F5.** ตัดสินใจเรื่องการพิมพ์ไพ่จริง (ถ้าจะทำ) ต้องเพิ่ม bleed, CMYK ฯลฯ ตาม `docs/06_QA_AND_PRINT_TH.md` ซึ่งยังไม่ได้ทำ

## ค่าที่ผมยังไม่ได้ตรวจกับเอกสารล่าสุด (ตรวจก่อน deploy)

- เพดานเวลา CPU และราคาของแพ็กเกจ Workers/D1 (เพดานขนาดฐานข้อมูล)
- เวอร์ชัน Graph API ของ Facebook (ในโค้ดคือ `v21.0` ตัวแปร `FB_VERSION` ใน `api/lib/social.mjs`)
- โควตาข้อความ push ของแพ็กเกจ LINE Official Account และการที่ LINE Notify ปิดบริการแล้ว (ระบบนี้ใช้ Messaging API)
- ข้อความของ Cloudflare เรื่อง Web Analytics ที่อ้างในนโยบาย (ช่อง `[ ]` ในหัวข้อคุกกี้)
- PBKDF2 600,000 รอบ: ตรวจแล้วว่าใช้ได้บน workerd ในเครื่อง ส่วนบน Cloudflare จริงยังไม่ได้ลอง (มีทางถอยอัตโนมัติไป 100,000 ถ้าถูกปฏิเสธ ดูบรรทัด `PBKDF2 count refused` ใน `wrangler tail`)

## ที่ไม่ได้ทำ (ตั้งใจ)

Apple Sign-In, 2FA ของผู้ใช้, Admin UI (จัดการเนื้อหาผ่าน Git + deploy ใหม่), คิวส่งอีเมลถาวร (ตอนนี้ลองซ้ำหนึ่งครั้ง), `deck_versions` + สคริปต์ publish, KV, Analytics Engine ทั้งหมดอยู่ในแผน `docs/08_BACKEND_ARCHITECTURE_TH.md` ถ้าต้องการเพิ่มภายหลัง
